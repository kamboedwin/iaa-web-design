01 / Start with meaning

What you will learn

HTML gives a webpage its structure: headings, paragraphs, links, tables and forms. CSS (Cascading Style Sheets) controls how that content is presented. It helps a library or records centre make information easier to read, recognise and navigate.

After studying this unit, you should be able to:

  1. Explain the purpose of CSS and distinguish it from HTML.
  2. Read and write CSS rules with selectors, properties and values.
  3. Apply CSS using inline styles, internal stylesheets and external stylesheets.
  4. Style headings, paragraphs, links, colours, fonts and simple page sections.
  5. Use element, class and ID selectors appropriately.
  6. Explain the basic idea of the cascade and why one declaration may override another.
  7. Style a fictional library or records-service webpage using a separate CSS file.
Connection to Unit 6: an HTML request form can work without decoration; CSS can make its labels, spacing and buttons clearer. Styling does not replace the correct HTML elements or secure data processing.

02 / Why CSS matters

Why CSS matters

Consider a library webpage containing a title, opening hours and a link to the catalogue. HTML identifies each item; CSS determines the appearance of each one. A page with consistent font sizes, spacing and colours is easier to scan than a page where everything looks alike.

HTML = meaning and structure

<h1> identifies the main heading; <a> identifies a link; <table> represents tabular data.

CSS = visual presentation

font-size controls how large text appears; color changes text colour; padding adds space inside an element.

Why separate them? One stylesheet can apply a consistent style across several webpages. Changing the colour or font once can update every page that uses that stylesheet.

In information services: a familiar appearance helps visitors distinguish navigation, service notices, catalogue links and public enquiry options.

03 / Anatomy of a CSS rule

Anatomy of a CSS rule

A CSS rule starts with a selector and contains one or more declarations inside curly braces. Each declaration contains a property, a colon, a value and a semicolon.

h1 {
  color: #155c5a;
  font-size: 32px;
}
h1 — selector

Finds all <h1> headings on the page.

color — property

Identifies which visual characteristic should change.

#155c5a — value

Specifies the new colour.

{ ... } — declaration block

Groups the declarations for the selector.

CSS comments use /* ... */. Comments can explain a rule but are not shown in the webpage.

/* Headings for service pages */
h2 { color: darkslateblue; }

Common mistakes include forgetting the colon, omitting the braces or writing a property name incorrectly. Browsers normally ignore invalid declarations rather than showing them as text.

04 / Three ways of adding CSS to HTML

Three ways of adding CSS to HTML

CSS may be included directly in an HTML element, placed in a <style> element, or saved in a separate .css file. All three approaches are useful to recognise; a separate stylesheet is generally the best choice when several pages share a design.

1. Inline CSS

<p style="color: green;">Library opening hours</p>

This styles one paragraph only. It is quick for a tiny example but repetitive when used throughout a website.

2. Internal CSS

<head>
  <style>
    p { color: #155c5a; }
  </style>
</head>

Rules inside <style> normally appear in the document's <head> and apply to matching elements on that webpage.

3. External CSS

<!-- In index.html, inside <head> -->
<link rel="stylesheet" href="styles.css">
/* In styles.css */
p { color: #155c5a; }

The HTML file links to a separate stylesheet. The file path must be correct. If styles.css is in a folder named css, the link becomes href="css/styles.css".

Important: a CSS file contains CSS rules, not an entire HTML document. The <link> element belongs in HTML; it does not belong inside the CSS file.
05 / Selecting the elements to style

Selecting the elements to style

A selector tells the browser which HTML elements should receive a set of declarations.

Selector typeCSS exampleWhich HTML matches?
Elementp { ... }All paragraphs
Class.notice { ... }Any element with class="notice"
ID#contact { ... }The element with id="contact"
Grouph1, h2 { ... }Both level-one and level-two headings
Descendantnav a { ... }Links contained within a <nav>

How to use a class

<p class="notice">The library closes at 5 pm.</p>

/* In the CSS */
.notice {
  background-color: #fff3d5;
  padding: 12px;
}

The dot in .notice is part of the CSS selector; it is not written in the HTML class value. A class can be reused on many elements. An ID is intended to identify one element within a document.

Tip: choose names that describe a role, such as notice or service-card, rather than a temporary appearance such as big-blue-box.

06 / How the cascade resolves competing rules

How the cascade resolves competing rules

The word cascading means that several CSS declarations can apply to the same element. The browser uses a set of rules to decide which declaration wins, including the origin, importance, specificity and order of declarations.

At beginner level, start with two useful ideas:

  1. When two equally important rules have the same specificity, the later matching declaration generally wins.
  2. An ID selector is usually more specific than a class selector, and a class selector is usually more specific than an element selector, when compared at the same cascade level.
p { color: blue; }
p { color: green; } /* Later rule wins here. */
p { color: blue; }
.notice { color: green; }

/* <p class="notice">Notice text</p> is green. */

Inheritance: some properties, such as color and font-family, can pass from a parent element to its children. Others, such as border, do not normally inherit.

Keep it simple: avoid relying on !important to solve beginner styling problems. Start by checking selector spelling, the linked file path, specificity and declaration order.
07 / Colours and backgrounds

Colours and backgrounds

The color property controls text colour, while background-color controls an element's background. You can use named colours, hexadecimal colour codes such as #155c5a, or functions such as rgb().

body {
  color: #20343e;
  background-color: #f5f8f7;
}
.notice {
  color: #5a3b08;
  background-color: #fff0cb;
}
Readable contrast

White text on a dark background is usually easy to read.

Quiet backgrounds

Soft backgrounds can separate service information.

Colour should not be the only way to communicate a status. A borrowing notice, for example, should also use descriptive words such as Available or On loan.

Avoid overly bright backgrounds behind long paragraphs, and keep links visibly recognisable.

08 / Fonts, spacing and readable text

Fonts, spacing and readable text

Text is the most important content on many information-service websites. CSS typography controls legibility and helps visitors identify titles, sections and instructions.

body {
  font-family: Arial, sans-serif;
  font-size: 16px;
  line-height: 1.6;
}
h1 { font-size: 2rem; }
a { text-decoration: underline; }
PropertyWhat it changesTypical use
font-familyTypefaceConsistent body text
font-sizeText sizeDistinguish headings from body text
font-weightText weightEmphasise important headings
line-heightSpace between linesImprove paragraph readability
text-alignHorizontal text alignmentLeft-align long reading passages
text-decorationDecoration, such as underlinesMake links identifiable

Units: px is a fixed CSS reference unit, while rem scales relative to the root element's font size. For many beginners, starting with a readable base and using rem for headings is sufficient.

09 / Backgrounds, borders, padding and margins

Backgrounds, borders, padding and margins

Almost every HTML element can be considered a rectangular box. CSS allows you to control the space around and inside that box.

Margin: space outside the border
Border and padding
Content

Library service information

In a real box, padding is inside the border and margin is outside it.

.service-card {
  background-color: #eff7f4;
  border: 1px solid #b7d7cc;
  padding: 16px;
  margin-bottom: 20px;
  border-radius: 8px;
}

padding prevents text from touching the edge of a card. margin separates it from neighbouring elements. Detailed box-model calculations and responsive layouts are introduced in Unit 8.

10 / Reusable styles for a consistent website

Reusable styles for a consistent website

A website becomes easier to maintain when the same visual treatment is reused. Suppose several library services should look like cards. Give each service element a class, then write the CSS once.

<section class="service-card">
  <h2>Borrowing</h2>
  <p>Find out how to borrow books.</p>
</section>
<section class="service-card">
  <h2>Reference services</h2>
  <p>Ask for help locating information.</p>
</section>
.service-card {
  padding: 16px;
  border: 1px solid #b7d7cc;
  border-radius: 8px;
  margin-bottom: 16px;
}

The two sections now have a consistent appearance. This is useful for services, catalogue categories, public notices and records-access instructions. Use semantic HTML elements and meaningful headings; CSS is a presentation layer rather than a substitute for document structure.

13 / Interactive: which rule wins?

Interactive: which rule wins?

A paragraph has class="notice". Consider these rules:

.notice { color: green; }

17 / Review and continue

Unit 7 summary

  • HTML describes content; CSS describes its appearance.
  • A CSS rule contains a selector and declarations made up of property–value pairs.
  • Styles can be inline, internal or external; external stylesheets support consistency across pages.
  • Element, class and ID selectors target different sets of HTML elements.
  • When rules compete, specificity and declaration order are among the factors that determine the result.
  • color, background-color, font-family, font-size, border, padding and margin are useful first properties.
  • Consistent styling helps visitors understand library and records-service information.
  • Good visual design keeps text readable and never replaces correct HTML or responsible data handling.
