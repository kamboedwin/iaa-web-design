01 / Learning to collect user input

What you will learn

Forms enable visitors to enter information into a webpage. A library might offer a book-request form; a records office might let visitors enquire about a published record or request guidance on access procedures. A form is the visible interface through which a user provides information.

After studying this unit, you should be able to:

  1. Describe what a form does and identify when it is appropriate.
  2. Create a form with meaningful label, input, textarea, select and button elements.
  3. Choose suitable types of input and group related choices.
  4. Use basic browser validation, including required.
  5. Explain the difference between the visible HTML interface and server-side processing.
  6. Create a simple form for a fictional library or records centre.
Connection to Unit 5: tables display existing structured information; forms allow a user to enter or choose information. A real system may combine both, but an HTML form alone is not a database.

03 / Understand the purpose

What is an HTML form?

An HTML form is a collection of controls—such as text boxes, radio buttons and a Submit button—that allows users to provide information. A form should request only information needed for a clear task.

Library example

A visitor enters a book title, chooses a collection point and supplies contact details to request assistance.

Records-management example

A visitor chooses a public record category, enters a fictional reference and describes an enquiry.

When designing a form, begin with the user's purpose: What does the visitor need to accomplish? Which fields are necessary? What will happen after the form is submitted?

Important distinction: the controls can be displayed using HTML alone. Saving, emailing, checking permissions or retrieving records normally requires processing beyond HTML, such as a server, authorised service or database.

04 / The outer form

The <form> element

The <form> element groups the controls to be submitted. Its action attribute identifies a destination, while method specifies how the browser sends form data, commonly get or post.

<form action="/requests" method="post">
  <label for="book">Book title</label>
  <input type="text" id="book" name="book" required>
  <button type="submit">Send request</button>
</form>

In this example, /requests represents a server endpoint. It is not automatically created by HTML. Without an appropriate processing service, the form cannot complete a real booking or request.

Read the code: the opening form tag starts the group; the label identifies the field; the input receives text; the button submits; and </form> closes the group.
05 / Accessible descriptions

Labels, id and name

Every input needs a meaningful description. The <label> element tells users what to enter, and a correctly linked label makes a control easier to use with a mouse, touch screen or assistive technology.

<label for="ref">Public reference code</label>
<input id="ref" name="reference" type="text">
  • for="ref" identifies the control whose id is ref.
  • id should be unique within the webpage.
  • name="reference" is the key used when the form data is submitted.
  • A placeholder is a hint, not a replacement for a visible label.
Try it: click a label in the live editor. With a correctly associated for and id, the labelled control receives focus.
06 / Choose the correct field

Text, email, telephone and longer answers

Different type values tell the browser what kind of entry is expected. The browser may offer an appropriate keyboard on a mobile phone or apply basic input checks.

type="text"Short general textBook title or public reference

type="tel"Telephone number entryContact phone
type="date"Date selectionPreferred visit date
type="number"Numeric quantityNumber of copies requested
<textarea>Several lines of textAdditional information about an enquiry
<label for="email">Email address</label>
<input type="email" id="email" name="email" required>

<label for="message">Enquiry details</label>
<textarea id="message" name="message" rows="4"></textarea>

Use the input type that matches the meaning of the information. For example, a telephone number can begin with a zero or plus sign, so type="tel" is more appropriate than type="number".

07 / Allow visitors to choose

Radio buttons, checkboxes and dropdowns

When the possible answers are known, provide clear choices instead of making visitors type everything.

Radio buttons: choose one

Radio buttons use the same name to form one group. Useful for selecting one collection point or preferred contact method.

Checkboxes: select independently

A checkbox can represent an agreement or an independent choice. Multiple checkboxes can be checked unless the page adds another rule.

<p>Collection point</p>
<label><input type="radio" name="point" value="main" checked>
  Main library</label>
<label><input type="radio" name="point" value="branch">
  Branch library</label>

<label><input type="checkbox" name="updates">
  Send me general service updates</label>

A <select> creates a dropdown containing <option> choices:

<label for="category">Public record category</label>
<select id="category" name="category" required>
  <option value="">Choose one</option>
  <option value="reports">Annual reports</option>
  <option value="guides">Service guides</option>
</select>

An initial option with an empty value, together with required, encourages visitors to make a deliberate selection.

08 / Make forms understandable

fieldset and legend

Related controls, especially radio buttons and checkboxes, are easier to understand when grouped together. A <fieldset> contains the group, and a <legend> gives that group a meaningful heading.

<fieldset>
  <legend>How should we contact you?</legend>
  <label><input type="radio" name="contact" value="email">
    Email</label>
  <label><input type="radio" name="contact" value="phone">
    Phone</label>
</fieldset>

Good forms follow the same usability principles studied in Unit 2: descriptive text, logical order, minimal unnecessary fields, sensible spacing and clear action buttons.

09 / Check entries before processing

Basic HTML form validation

HTML provides simple browser-side validation. For example, required can stop an empty field from being submitted; type="email" checks basic email-address format; and minlength, maxlength, min and max can express other limits.

<label for="title">Book title</label>
<input id="title" name="title" type="text"
       required minlength="3" maxlength="80">

<label for="copies">Number of copies</label>
<input id="copies" name="copies" type="number"
       min="1" max="3" value="1">

Example: if the book title is blank, the browser can ask the visitor to complete it. If an email field contains an invalid address format, the browser can ask for correction.

Limit: browser validation does not establish whether an email is real, whether a record exists or whether a person is authorised to access information. Real services must check submitted data and access rights on the server as well.
10 / Understand what happens next

GET, POST, submission and privacy

A form usually sends data to a processing destination. Two common HTTP methods are:

GET

Appends submitted values to the URL as a query string. Suitable for public searches, such as looking up a book by keyword. Values may appear in browser history or logs.

POST

Sends submitted values in the HTTP request body instead of the URL query string. Used for operations such as submitting a service request. POST alone does not provide encryption.

<!-- Public search: results can be represented in a URL -->
<form action="/catalogue/search" method="get">
  <label for="q">Search books</label>
  <input id="q" name="q" type="search">
  <button type="submit">Search</button>
</form>

For sensitive information, a real system should use HTTPS, server-side validation, appropriate authentication and access control. Do not put confidential records or personal identifiers into a publicly accessible exercise or URL.

Use <button type="submit"> to submit a form and <button type="button"> for an action that should not submit it. A reset button returns controls to their initial values, but may erase work unexpectedly; use it only when it is genuinely helpful.

17 / Review the essentials

Unit 6 summary

  • HTML forms allow visitors to enter data and choose options.
  • <form> groups the controls; action and method describe submission.
  • Labels, unique IDs and meaningful names make fields understandable and usable.
  • Use textarea for longer text, radio buttons for one choice, checkboxes for independent choices and dropdowns for predefined options.
  • fieldset and legend describe groups of controls.
  • required and input types help with basic browser checks but do not replace server validation.
  • HTML does not by itself store or authorise access to submitted records.
  • Requests for personal or confidential information require responsible data handling and appropriate security controls.
