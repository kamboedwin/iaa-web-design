01 / Begin building

What you will learn

In Unit 2, you planned what a useful webpage should contain. Now you will create that content using HTML (HyperText Markup Language). HTML gives a webpage its structure and meaning: for example, it identifies a main heading, a paragraph, or important information. A browser interprets HTML and presents the content on screen.

A library website might use HTML to introduce borrowing services. A records-centre website might explain how a visitor requests access to a record. At this stage, a useful webpage can be built without a database, JavaScript or an Internet connection.

By the end of this unit, you should be able to:

  1. Explain HTML and its relationship to CSS and JavaScript.
  2. Recognise the required parts of a modern HTML document.
  3. Distinguish tags, elements and attributes, and nest elements correctly.
  4. Write headings, paragraphs, line breaks, emphasis and comments appropriately.
  5. Save, open, edit and troubleshoot a webpage on your computer.
  6. Create a basic information page for a fictional library or records centre.
Important distinction: HTML describes content and meaning. CSS controls much of its appearance; JavaScript can add behaviour. HTML on its own does not create a secure records system or library database.

02 / The language of webpages

What is HTML?

HTML is the standard markup language used to structure content on the Web. HyperText refers to connected information, often through links; Markup means labels inserted into a document to indicate the role of its parts. A heading is not merely text written in a large font: it is identified as a heading with an HTML element.

HTML: structure

Identifies headings, paragraphs, links, lists, tables, images and forms.

<h1>Our Library</h1>

CSS and JavaScript: later steps

CSS controls presentation, such as layout, colour and spacing. JavaScript can respond to events and change content. Both are introduced later in the course.

HTML is commonly called a markup language rather than a general-purpose programming language. It identifies the structure of content but does not, by itself, implement database queries, authenticate borrowers or securely process records requests.

The browser reads the HTML file and constructs a document tree from the elements. It then displays the page using its own default styles unless other styles are supplied.

03 / A complete document

The standard HTML document structure

Most HTML webpages begin with a document declaration and contain two major sections: <head> for information about the page and <body> for the content visitors see.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Community Library</title>
</head>
<body>
  <h1>Welcome to Community Library</h1>
  <p>Find books and study support in one place.</p>
</body>
</html>
PartMeaning and purpose
<!DOCTYPE html>Declares that the document uses modern HTML. It is a declaration, not an HTML tag.
<html lang="en">Root element containing the webpage; lang describes the primary language (English in this example).
<head>Stores metadata and references, such as page title and character encoding. Most head contents are not shown in the page itself.
<meta charset="UTF-8">Specifies Unicode text encoding so letters and symbols can be represented correctly.
<meta name="viewport" ...>Helps the page use the device width as the initial layout viewport; useful on phones.
<title>Names the page in the browser tab and is useful for bookmarks and search results. It is different from a visible <h1>.
<body>Holds the visible content: headings, paragraphs and, later, lists, links, images and forms.
Check your understanding: A page whose <title> says “Community Library” but whose <h1> says “Borrowing Services” will show “Community Library” in the browser tab and “Borrowing Services” as its main on-page heading.
04 / Reading HTML syntax

Tags, elements and correct nesting

HTML uses tags enclosed in angle brackets. Most elements have an opening tag, content and a closing tag. A complete element includes these parts together.

<p>Library opening hours are available here.</p>
Part of exampleExplanation
<p>Opening tag: starts a paragraph.
Library opening hours are available here.Content of the element.
</p>Closing tag: ends the paragraph; note the slash.

Elements can be nested, meaning one is placed inside another. Nested elements should be closed in the reverse order in which they were opened.

Correct nesting

<p>Ask a <strong>librarian</strong> for help.</p>

Incorrect nesting

<p>Ask a <strong>librarian</p></strong> for help.

This closes the paragraph before closing the bold-emphasis element.

Some HTML elements, such as <br>, <hr> and <meta>, are void elements: they do not wrap content and have no closing tag. An image element (<img>) is also void and will be explained in Unit 4.

05 / Extra information in tags

Understanding HTML attributes

An attribute adds information to an element. It appears in the opening tag and usually uses name="value" notation. Quote marks are a good beginner habit because they make values clear.

<html lang="en">
<p id="opening-hours" title="Public service hours">We open at 8 a.m.</p>
AttributeWhat it communicates
lang="en"English is the primary language of the document, assisting browsers and assistive technologies.
id="opening-hours"Gives one element a unique identifier within the page.
class="service"Places elements in a reusable group for later CSS and JavaScript.
title="Public service hours"Provides advisory text; it is not a substitute for visible labels or important information.

Later units introduce attributes such as href for links and src/alt for images. Attribute values should be meaningful and not used to store confidential records.

06 / Organising readable information

Headings, paragraphs, breaks and separators

Use headings to organise ideas into a clear hierarchy. <h1> represents the main page heading, while <h2> to <h6> represent progressively deeper subsections. Choose heading levels by structure rather than by the appearance you want.

<h1>Community Library</h1>
<h2>Borrowing Services</h2>
<h3>Loan Periods</h3>
<p>Students may borrow items under library rules.</p>

A paragraph uses <p>. Browsers generally collapse extra spaces and line breaks in source code into a single space when displaying ordinary text. To create a new paragraph, start another <p> rather than inserting many blank lines into the editor.

<p>Request guidance at the records office.</p>
<p>Office hours: Monday to Friday.</p>

<br> adds a line break within content where a line break is meaningful, such as an address. <hr> indicates a thematic break between topics. Neither should be used simply to push things apart visually; CSS will handle spacing later.

07 / Meaningful emphasis

Strong importance, emphasis and special characters

<strong> indicates strong importance, and <em> indicates stress emphasis. Browsers often display these as bold and italic text, but their purpose is meaning, not merely decoration.

<p><strong>Important:</strong> Bring your membership card.</p>
<p><em>Only authorised users</em> may request restricted records.</p>

If an ordinary paragraph needs to display literal characters that HTML normally treats as markup, use character references (also called entities). Examples: &lt; displays <; &gt; displays >; and &amp; displays &.

<p>Research &amp; Learning Services</p>
<p>To show a tag, write &lt;p&gt; in the source.</p>

For example, the actual source of a heading may be <h1>Records Office</h1>, but writing those angle brackets as unescaped text within a paragraph may cause the browser to treat them as tags instead of displaying them.

08 / Helpful source notes

HTML comments and good source-code habits

Comments are notes in the source code intended for people reading or maintaining it. A browser normally does not show comment text as visible page content.

<!-- Main information shown to visitors -->
<h1>Records Centre</h1>
<!-- Update these hours when the service changes -->
<p>Opening hours: 9 a.m. to 4 p.m.</p>

Use simple indentation, descriptive page titles and consistent lowercase element names to make files easier to read. HTML element names are generally case-insensitive in HTML documents, but lowercase is a useful convention.

Privacy note: Comments are not secret. Someone can view the HTML source in a browser. Never put passwords, personal records, access tokens or confidential notes in HTML or comments.
09 / Working on your computer

Write, save, open and troubleshoot an HTML file

  1. Open a plain-text editor. You can use Notepad (Windows), Visual Studio Code, or another text editor. A word processor such as Microsoft Word is not ideal because it may save extra formatting.
  2. Type or paste the HTML document. Keep the structure intact and edit the title, heading and paragraphs.
  3. Save as index.html. In Windows Notepad choose Save as type: All files and UTF-8 encoding if offered. Avoid accidentally creating index.html.txt.
  4. Double-click the file or choose Open with and your web browser. The address may begin with file:/// because the page is stored locally.
  5. Return to the editor, make a change, save and refresh the browser. A browser may display an old version until you refresh it.

If the page shows tags as text

Check that the file is .html, not .txt, and that the browser is opening the correct file.

If text appears in the wrong place

Check opening and closing tags, nesting and whether content intended for the page is inside <body>.

Developers can also use a browser’s View Page Source or Developer Tools to inspect HTML. These are useful for learning but do not give permission to access restricted information. A standards-based HTML validator can help identify problems such as incorrectly nested tags.

11 / Applying HTML to professional work

Examples for library and records-management students

Library and Information Studies

Library service information

A simple public page can identify the library, introduce borrowing services and explain when a visitor can ask for help.

<h1>Community Library</h1>
<h2>Borrowing Services</h2>
<p>Ask our staff about borrowing rules.</p>
Records Management Systems

Records-centre information

A public-facing page can explain service hours, request procedures and where to obtain guidance without revealing protected documents.

<h1>District Records Centre</h1>
<h2>Request Guidance</h2>
<p>Contact the office before requesting access.</p>

Notice: both examples use exactly the same HTML concepts. The professional context changes the content, not the underlying technology. Links, lists, tables and forms will be developed in later units.

12 / Guided practice

Practical: build your first information webpage

Estimated practice time: 20–30 minutes. A computer and a plain-text editor are sufficient; an Internet connection is not needed.

  1. Download the starter ZIP and extract index.html, or create your own file using the document structure above.
  2. Choose a fictional library or records centre. Change the text inside <title> and <h1> to match your choice.
  3. Add one <h2> describing a service and a <p> explaining it in two sentences.
  4. Add one more paragraph containing <strong> or <em> where appropriate.
  5. Save the file as index.html. Open it in a browser and check the heading order, text and browser-tab title.

14 / Short individual assignment

Assignment 3 — My first HTML webpage

Create one simple HTML page for a fictional library or records centre. This assignment uses the HTML covered in Unit 3 and does not require CSS, JavaScript or a database.

  1. Include a meaningful browser-tab <title> and one main <h1> heading.

15 / Key points

Unit 3 summary

  • HTML gives webpages structure and meaning through elements.
  • A complete document usually has a declaration, <html>, <head> and <body>.
  • Tags mark elements; attributes provide additional information in opening tags.
  • Headings represent hierarchy; paragraphs group written information.
  • Meaningful emphasis and well-formed nesting improve clarity.
  • Source comments are visible to anyone inspecting code and should never contain secrets.
  • Saving a plain-text file with the .html extension and opening it in a browser is enough to create a basic webpage.
