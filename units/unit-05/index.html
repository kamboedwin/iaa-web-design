01 / Introducing tabular information

What you will learn

Libraries and records centres often need to show lists of related facts. A catalogue may have a book title, author, publication year and availability status. A records inventory may have a category, reference, year and access classification. When information follows a consistent pattern, an HTML table helps a reader compare entries.

By the end of this unit, you should be able to:

  1. Explain why a table is suitable for some information and unsuitable for page layout.
  2. Build rows and cells using <table>, <tr> and <td>.
  3. Label columns and rows with <th> and scope.
  4. Add a descriptive <caption> and group rows using <thead>, <tbody> and <tfoot>.
  5. Recognise when colspan and rowspan may be needed.
  6. Create a small catalogue or records inventory using fictional data.
Connection to Unit 4: Your website can include a Collections or Public records page. This unit provides the HTML structure for presenting the entries on that page.

03 / Choose the right structure

What is an HTML table?

An HTML table is a set of data cells arranged in rows and columns. Data in the same column normally has a shared meaning. For example, every value under Availability indicates whether an item may be borrowed.

Example: three library books

Sample library catalogue
Book titleAuthorStatus
Information ServicesA. MremaAvailable
Digital CollectionsN. JumaOn loan
Archives and SocietyP. LemaAvailable

A table is most helpful when visitors need to compare structured data. Do not use a table merely to place pictures, paragraphs or menus into columns. Later, CSS layout tools will be used for page design.

Good use: opening-hour schedules, book catalogues, public inventories, published service fees.
Not a good use: putting an entire homepage into a table to control where each section appears.
04 / Build a table step by step

Rows, data cells and header cells

HTML uses a small set of elements to describe a table. A <table> contains rows (<tr>). Each row contains cells. Ordinary data cells use <td>; heading cells use <th>.

ElementMeaningWhat it does
<table>TableContains the tabular information
<tr>Table rowGroups cells horizontally
<th>Header cellIdentifies the meaning of a row or column
<td>Data cellContains a value

The first working table

<table>
  <tr>
    <th>Book title</th>
    <th>Status</th>
  </tr>
  <tr>
    <td>Digital Libraries</td>
    <td>Available</td>
  </tr>
</table>

Read the structure from the outside in: table → tr → th or td. The first row contains the labels. The second row holds one book entry. Another book would require another <tr> with matching cells.

Count carefully: the example has two rows and two columns. The header row also counts as a row.
05 / Make the meaning explicit

Captions, column headers and row headers

A table can be difficult to understand if the reader does not know what its entries represent. The <caption> element supplies a short description of the whole table. It is written immediately after the opening <table> tag.

The scope attribute clarifies which cells a header describes:

  • <th scope="col"> labels the data below it in a column.
  • <th scope="row"> labels the data alongside it in a row.
<table>
  <caption>Library opening hours</caption>
  <tr>
    <th scope="col">Day</th>
    <th scope="col">Hours</th>
  </tr>
  <tr>
    <th scope="row">Monday</th>
    <td>08:00–17:00</td>
  </tr>
  <tr>
    <th scope="row">Saturday</th>
    <td>09:00–13:00</td>
  </tr>
</table>

Here Day and Hours are column headers, while Monday and Saturday identify individual rows. The structure helps everyone, including readers using screen readers, understand which values belong together.

06 / Structure larger tables

Using thead, tbody and tfoot

HTML lets you group a table into three sections. These do not create new columns; they describe the purpose of particular rows.

SectionRole
<thead>One or more rows containing column headings
<tbody>The main data rows
<tfoot>Summary, totals or concluding rows when relevant
<table>
  <caption>Publications by type</caption>
  <thead>
    <tr><th scope="col">Type</th><th scope="col">Count</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Books</th><td>24</td></tr>
    <tr><th scope="row">Reports</th><td>6</td></tr>
  </tbody>
  <tfoot>
    <tr><th scope="row">Total</th><td>30</td></tr>
  </tfoot>
</table>

The <tfoot> section is optional. A basic book list usually needs only a header and body; a totals row is useful when the numbers have a meaningful sum.

08 / Advanced cells in simple form

Using colspan and rowspan

Most tables are easiest to understand when every row has the same number of columns. Sometimes a cell must cover more than one column or row. HTML provides colspan and rowspan for this purpose.

colspan: join columns

<table>
  <tr><th colspan="2">Library contact details</th></tr>
  <tr><th scope="row">Telephone</th><td>Office line</td></tr>
  <tr><th scope="row">Location</th><td>Reading hall</td></tr>
</table>

colspan="2" means the first header occupies the width of two columns. Do not add a second cell in that first row.

rowspan: join rows

<table>
  <tr>
    <th scope="col">Area</th><th scope="col">Service</th>
  </tr>
  <tr>
    <th scope="row" rowspan="2">Library</th>
    <td>Reading space</td>
  </tr>
  <tr><td>Reference help</td></tr>
</table>

rowspan="2" means the Library cell occupies two rows. The following row therefore includes only the other data cell. Use spanning sparingly: complicated tables may be harder to read and use with assistive technology.

09 / Write trustworthy HTML

Common mistakes and table readability

MistakeWhy it mattersBetter approach
Using <td> for every labelHeaders are not identifiedUse <th scope="col"> or scope="row"
Different accidental cell countsValues may appear under the wrong headingCount the columns and check every row
Missing closing tagsBrowsers may rearrange unexpected markupClose tr, td, and th correctly
Table without a captionPurpose may be unclearAdd a concise <caption>
Very wide tableHard to read on a small screenUse concise headings and horizontal scrolling or simplify columns

HTML controls the meaning and structure of the table. The browser decides how an unstyled table appears. CSS can later add borders, spacing, background colours and improved presentation without changing its meaning.

A small CSS preview

<style>
  table { border-collapse: collapse; width: 100%; }
  th, td { border: 1px solid #bbc9c8; padding: 0.6rem; }
  th { background: #e8f3ef; text-align: left; }
</style>

You do not need to memorise the CSS yet. Unit 7 will explain these rules in detail. In this unit, focus on writing a correct HTML table first.

15 / Consolidate your knowledge

Unit 5 summary

  • HTML tables organise related data in rows and columns.
  • <table> contains the table; <tr> creates a row; <td> creates a data cell.
  • <th> creates a header, and scope helps describe whether it labels a column or row.
  • <caption> states the purpose of the table.
  • <thead>, <tbody> and <tfoot> help group table rows.
  • colspan and rowspan join cells only when there is a genuine relationship.
  • Tables are suitable for structured information, not general webpage layout.
