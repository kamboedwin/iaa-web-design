01 / Start here

What you will learn

Webpages are opened on phones, tablets, laptops and larger monitors. A useful website keeps its content readable and its controls easy to use on all of them. Responsive web design is the practice of creating layouts that adapt to the available space.

By the end of this unit, you should be able to:

  1. Distinguish a fixed-width page from a flexible, responsive layout.
  2. Explain the content, padding, border and margin parts of the CSS box model.
  3. Use width, max-width and box-sizing to control element dimensions.
  4. Build a simple row of service cards with Flexbox and gap.
  5. Write a basic @media rule to change a layout at wider screen sizes.
  6. Check that images, navigation and long tables can be used on narrow screens.
  7. Make one small webpage respond to different browser widths.
Connection to Unit 7: you already know how CSS rules change colours, text and spacing. This unit uses CSS to control where elements appear and how their arrangement changes.

03 / Think about real users

What is responsive web design?

Responsive design means that a webpage adjusts its layout as the available screen space changes. The same content may appear as three cards side by side on a desktop but as one column on a phone. The information remains available without forcing a visitor to zoom out to read tiny text.

Fixed-width layout

A container set to width: 1100px may extend beyond a narrow phone screen. Visitors have to scroll sideways to read content or reach buttons.

Flexible layout

A container using width: 100% with a sensible max-width can fill smaller screens without becoming excessively wide on larger ones.

Responsive design is more than making everything smaller. Useful layouts may rearrange columns, wrap navigation links, increase available space for text, or allow an exceptionally wide table to scroll within its own container.

Example: a student viewing library opening hours on a phone should see the times clearly and reach the catalogue link without horizontal scrolling.
04 / The browser's viewing area

The viewport and mobile-first thinking

The viewport is the area the browser uses to display a webpage. On a small device, less horizontal space is available. Include the viewport meta tag in the document's <head> so mobile browsers use the intended device-width layout.

<meta name="viewport" content="width=device-width, initial-scale=1">

Mobile-first design begins with a clear, single-column layout that works on small screens, then introduces wider arrangements where there is enough space. This encourages you to prioritise the most useful information.

/* Small screens: one column */
.services { display: flex; flex-direction: column; gap: 16px; }

/* Wider screens: two columns */
@media (min-width: 720px) {
  .services { flex-direction: row; }
}

The breakpoint 720px is an example, not a universal rule. Choose breakpoints according to when your actual content needs more space.

05 / Understand each element's space

The CSS box model

The browser lays out most HTML elements as rectangular boxes. The CSS box model describes four layers:

MARGIN
BORDER
PADDING
CONTENT
Text or image

Inside the border

Content is the text or image. Padding adds breathing room between the content and the border. A border surrounds the padded content.

Outside the border

Margin creates space outside the border, separating an element from neighbouring elements. Margins are transparent.

For a box with width: 320px, padding: 20px on each side, and a 2px border on each side, the default content-box total outer width is 320 + 40 + 4 = 364px, not counting margins.

.service-card {
  box-sizing: border-box;
  width: 320px;
  padding: 20px;
  border: 2px solid #165f65;
}

With box-sizing: border-box, the declared width of 320px includes the padding and border. This is usually easier to manage in responsive layouts.

06 / Make widths flexible

Width, maximum width and safe sizing

A page should use the available space without letting long paragraphs stretch across a very wide monitor. Combine flexible width with a maximum width.

* { box-sizing: border-box; }
.page-wrap {
  width: 100%;
  max-width: 1000px;
  margin-inline: auto;
  padding: 20px;
}

width: 100% allows the element to fit its available container width. max-width: 1000px prevents it growing wider than 1000 pixels. margin-inline: auto centres it when spare horizontal space exists.

Common error: a fixed width: 1000px can overflow a phone. Prefer flexible widths, check long words and code samples, and test the result at different widths.
07 / Organise related information

Spacing and visual grouping

Spacing helps visitors distinguish sections without adding extra decoration. Use padding inside cards, margin to separate larger sections, and gap to separate items inside Flexbox or Grid containers.

.service-card { padding: 18px; }
.service-section { margin-block: 28px; }
.service-list { display: flex; gap: 16px; }

For example, a records centre might group Public Enquiries, Records Retrieval and Retention Guidance into separate cards. Clear and consistent spacing helps a visitor scan those services.

Avoid creating spacing by typing many spaces or using repeated <br> elements. CSS spacing properties are more predictable.

08 / Arrange components

Build flexible layouts with Flexbox

Flexbox is a CSS layout system for arranging items in a row or column. Apply display: flex to a parent element; its direct children become flex items.

.services {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}
.service-card {
  flex: 1 1 240px;
}

Here flex-wrap: wrap lets cards move to another row when they do not fit. flex: 1 1 240px expresses a preferred item size of 240px, while allowing growth and shrinkage as available space changes.

Other useful Flexbox properties include flex-direction (row or column), justify-content (along the main axis), and align-items (across the main axis). The direction of those axes changes when the flex direction changes.

09 / Change layout when necessary

Use CSS media queries

A media query conditionally applies CSS rules. A width-based query can switch from one column to two when the available viewport becomes wide enough.

.services { display: flex; flex-direction: column; gap: 16px; }
@media (min-width: 720px) {
  .services { flex-direction: row; }
  .service-card { flex: 1; }
}

In the example, phones use one column by default. When the viewport reaches 720 CSS pixels, the cards sit in a row. A tablet or a laptop can still use one column if the content needs it; the correct breakpoint depends on the design.

Important: media queries do not require JavaScript. The browser applies the appropriate CSS automatically when its viewport changes.

10 / Keep essential links usable

Responsive menus and readable navigation

A long row of navigation links can become difficult to use on a narrow screen. A simple introductory approach is to allow the links to wrap, or stack them vertically on smaller screens. More advanced menu buttons need accessible interaction behaviour, not just visual styling.

.site-nav { display: flex; flex-wrap: wrap; gap: 12px; }
.site-nav a { padding: 10px 12px; }
@media (min-width: 720px) {
  .site-nav { justify-content: flex-end; }
}

Navigation links should remain visible, understandable, and operable with keyboard as well as touch. Avoid text that is too small to read and buttons that crowd one another.

11 / Make other content fit

Responsive images and wide tables

Images should not extend beyond their containers. A simple rule lets images scale down while preserving their proportions:

img { max-width: 100%; height: auto; }

Tables, such as a records inventory with many columns, may still need more width than a phone provides. Keep a meaningful HTML table and place it inside a horizontally scrollable wrapper:

<div class="table-scroll">
  <table>...</table>
</div>

.table-scroll { overflow-x: auto; }

In this case, only the table area scrolls sideways; the entire webpage should not. Headings and column headers must remain understandable.

12 / Check what users experience

Test layouts and correct common mistakes

Resize your browser or use its responsive device mode. Examine the page at about 360–390px (phone), 768px (tablet) and 1200px (desktop). These are useful test sizes, not strict device categories.

Check usability

  • Can you read every paragraph without horizontal page scrolling?
  • Can you reach navigation and form controls?
  • Do image and card widths fit the available space?
  • Does the page remain usable when text is enlarged?

Look for layout errors

  • Fixed widths wider than the screen.
  • Cards or images that cannot shrink.
  • Navigation links covering other content.
  • Tables pushing the whole page sideways.

Test with the content that the page will actually show. A short example heading may fit at one width while a longer real heading wraps onto two lines.

19 / Consolidate the ideas

Unit 8 summary

  • Responsive design adapts page layouts to available space without sacrificing readability.
  • The viewport meta tag helps mobile browsers use device-width layouts.
  • The CSS box model includes content, padding, border and margin.
  • box-sizing: border-box makes declared widths include padding and borders.
  • Flexible widths and max-width help content fit smaller screens.
  • Flexbox, wrapping and gap organise service cards.
  • Media queries apply layout changes when conditions, such as viewport width, are met.
  • Test menus, images, tables and long text at different screen widths.
