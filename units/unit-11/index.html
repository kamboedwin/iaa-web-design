01 / Start here

What you will learn

Libraries, archives and records centres use websites for more than publishing contact information. Visitors may search collections, request public information, read institutional publications or discover archived materials. Behind a useful interface there may be specialist software, a database and staff workflows.

By the end of this unit, you should be able to:

  1. Distinguish an ordinary information website from a web-based information system.
  2. Explain the purpose of an online public access catalogue (OPAC), integrated library system, digital repository, archival description system and electronic records-management system.
  3. Recognise the roles of content management systems, databases, back-end services and APIs.
  4. Describe why access permissions, metadata, privacy and records life-cycle controls matter.
  5. Recommend a suitable system type for a simple fictional information-service scenario.
Connection with earlier units: HTML structures the pages you see, CSS presents them clearly, and JavaScript can help visitors interact with them. This unit looks at the larger information systems behind those interfaces.

03 / Understand the difference

Information website versus information system

A website is a collection of webpages that people open in a browser. For example, a college library website may contain opening hours, rules, staff contacts, downloadable guides and links to other services. A simple information website can often be built using the HTML, CSS and introductory JavaScript you have already learned.

A web-based information system goes further. It supports actions such as searching an organised catalogue, showing item availability, managing authorised records or submitting a request for processing. Its visible webpages are only one part of the system.

Two different kinds of library web service
FeatureInformation websiteWeb-based system
Typical contentOpening hours, contacts, guidesSearchable collection, availability, account information
Where information may be keptHTML files or a content systemDatabase and specialist application services
User interactionNavigate and read public informationSearch, filter or carry out authorised transactions
SecurityProtect editing and hosting accessAlso enforce user permissions and protect transactions

Important: a website can also use a content management system, and a specialist system may contain mostly public pages. The distinction is about its function, not simply its visual appearance.

04 / See the whole picture

How a web information service works

Many web information systems use several connected components. The frontend is what visitors see and use. The backend processes requests and applies rules. The database stores and retrieves structured information. An API (application programming interface) is a defined way for software components to exchange information.

1Visitor's browserSearch form, results page, accessibility
↓ Request · ↑ Response
2Application / backendSearch logic, validation, access controls
↓ Query · ↑ Data
3Database and managed filesMetadata, records, audit information

Consider a book search. The visitor enters a title in a browser. The application searches catalogue records stored in a database and returns matching entries. The visitor sees a results page; authorised staff may have additional tools to update catalogue information.

Do not confuse: HTML tables and HTML forms show or collect information in a webpage. They do not, by themselves, create a database, a secure user account or an institutional workflow.
05 / Libraries

Online catalogues and integrated library systems

An online public access catalogue (OPAC) is a searchable interface for finding library materials. A visitor may search by title, author, subject or keyword, then inspect bibliographic information such as edition, publication details, call number or item availability, where provided.

An integrated library system (ILS) supports library operations such as cataloguing, circulation, acquisitions and patron management. The public catalogue is often one part of the larger ILS. Koha is an example of a free and open-source integrated library system.

Library example: finding a book

  1. A visitor opens the catalogue and searches for Introduction to Records Management.
  2. The catalogue displays matching bibliographic records.
  3. The visitor examines details such as title, author, classification and location.
  4. Where the catalogue supports it, the visitor checks whether a physical copy is available.

These features require accurate catalogue data and appropriate application services, not just a decorative search box.

06 / Digital collections

Digital libraries and institutional repositories

A digital repository stores, describes, manages and provides access to digital objects such as theses, research articles, datasets, images and other institutional materials. A repository may support searching, browsing, item pages, file downloads, identifiers and access restrictions.

DSpace is an open-source repository platform used by research and educational institutions. A college repository might make approved dissertations or journal articles discoverable while controlling access to material that cannot be openly distributed.

Catalogue recordRepository item
May describe a physical book and its locationMay describe and provide access to a digital thesis or article
Often supports discovery and availability checkingOften supports discovery, persistent identification and digital file access
A physical copy may remain on a shelfA managed digital file may be provided through the repository

Metadata means information that describes an information resource. An item title, creator, date, subject and identifier can all be metadata. Good metadata helps people find the right material and understand what it is.

Explore: DSpace.

07 / Archives

Archival descriptions and finding aids

Archives often hold groups of related records whose meaning depends on context: who created them, why they were created, and how they relate to other records. An archival finding aid describes holdings and helps researchers locate relevant collections, series or files.

ArchivesSpace is an example of an open-source archives information management application. It supports description and web access to archival holdings. It is not itself a complete digital-file storage or digitisation workflow solution.

Archive example: historical municipal minutes

A researcher may browse a finding aid for a local government collection, view its date range, read the scope-and-content description, and discover the reference code for a series of meeting minutes. Access to the physical or digital items may require a separate request or system.

08 / Records management

Electronic records-management systems

An electronic records-management system (ERMS) helps organisations capture, classify, maintain, find and manage electronic records according to approved rules. An electronic document and records-management system (EDRMS) may combine document-working functions with formal records management controls. Exact features vary between products.

A managed record is not merely a file on a website. An organisation may need a retention schedule, access restrictions, metadata, version or audit history, and a controlled process for authorised disposition.

CaptureRecord created or received
ClassifyApply identifier and metadata
Maintain and usePreserve integrity; control access
DispositionRetain, transfer or dispose under rules

For example, a government registry may need to register a document, associate it with a file reference, limit access to authorised staff and retain it for an approved period. A simple public HTML form cannot fulfil all these requirements.

Explore: National Archives — Universal ERM Requirements.

09 / Managing website content

Content management systems (CMS)

A content management system (CMS) helps authorised users create, organise, update and publish website content through an administrative interface. Examples include general-purpose platforms such as WordPress and Drupal. A CMS can be useful when several staff members update public notices, service descriptions, guides or news.

A CMS is different from an ILS or a dedicated ERMS. A CMS mainly manages content and presentation; specialist systems manage library operations or controlled records processes. Some institutions connect several systems to provide one coherent web experience.

Example: A college website may use a CMS for its homepage, link to a Koha catalogue for book discovery, and link to a DSpace repository for research outputs. These tools have different roles.

11 / Protect information

Metadata, access and information security

Information professionals need to distinguish public information from restricted information. A public catalogue may show book titles and locations, while borrower details are normally protected. A public records portal may explain request procedures but should not expose confidential personnel or financial records.

  • Authentication: verifying who a user is, such as through an institutional sign-in.
  • Authorisation: deciding which information and actions that user is allowed to access.
  • Privacy: handling personal information responsibly, including not collecting or publishing more than necessary.
  • Integrity: protecting records against unauthorised or accidental alteration.
  • Audit trail: recording relevant actions, such as changes to or access of controlled records, where required.
  • Backup and preservation: protecting long-term availability and recoverability using appropriate organisational practices.

Remember: hiding a link with CSS or JavaScript does not protect the information behind it. Access control must be enforced by a trusted application or service.

12 / Bringing services together

One institution may use several web systems

A single institutional website may help visitors reach multiple specialist systems. Users benefit when menus, wording and guidance make the destination of each link clear. Information professionals often help define user needs, metadata, permissions, content quality and service procedures while collaborating with technical teams on implementation.

LIBRARY

College library services

Public website for opening hours → catalogue for books → repository for theses → staff services for authorised transactions.

RECORDS

Records centre services

Public guidance for requests → enquiry channel → controlled records system for authorised classification, retrieval and retention.

17 / Simple independent task

Assignment 11 — Recommend an information service

Choose one of the two situations:

  • Library: A college wants students to find available books and read approved electronic dissertations.
  • Records centre: A public office wants visitors to understand how to request public records, while staff keep restricted records under authorised control.

In approximately 120–150 words, identify two suitable website or system features, explain their purpose, and mention one important privacy or access consideration. Use the concepts from this unit rather than describing how to program the systems.

Prepare: one short document or neatly written response. No HTML coding or software installation is required.

18 / Essential points

Unit 11 summary and further reading

  • A website may provide information on its own or serve as an interface to specialist information systems.
  • An OPAC helps people discover library resources; an ILS supports broader library operations.
  • Digital repositories manage digital resources; archival systems describe archival holdings and support discovery.
  • Records-management systems enforce records rules across capture, use, retention and disposition.
  • CMS platforms help staff publish website content; databases and back-end applications support organised and controlled information services.
  • Metadata, permissions, privacy, integrity and preservation are essential when information matters beyond a demonstration webpage.
