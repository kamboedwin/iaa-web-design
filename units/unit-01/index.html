01 / Getting started

What you will learn

Web design is the process of planning and creating websites that people can understand and use. This course introduces the underlying technology while keeping attention on users' needs. A well-designed website is not simply attractive; it helps visitors find information and complete tasks safely and efficiently.

By the end of this unit, you should be able to:

  1. Distinguish between the Internet and the World Wide Web.
  2. Define common web terms, including browser, webpage, website, URL, server, domain name and hosting.
  3. Explain, in simple steps, how a browser retrieves a webpage.
  4. Describe the different roles of HTML, CSS and JavaScript.
  5. Recognise basic website types and distinguish static pages from services that process data.
  6. Identify two useful and safe website features for a library or records centre.
  7. Create and open a very simple HTML file in a browser.
Learning approach: first understand the vocabulary, then explore a real website, try a small example, and consider how it can help information-service users. No programming experience is needed.

Preparation: use a laptop or desktop computer where possible. You need a modern browser and a plain-text editor such as Notepad or VS Code. You do not need to install a web server for this first unit.

02 / Basic concepts

Internet versus World Wide Web

The Internet is a worldwide system of interconnected computer networks. It provides infrastructure for devices and networks to exchange data using agreed communication rules called protocols. Email, messaging, file transfer and the Web are examples of services that use the Internet.

The World Wide Web (WWW) is a collection of interlinked resources, such as webpages, images and web applications, commonly accessed through web browsers over the Internet. Websites use technologies such as URLs, HTTP/HTTPS and HTML.

Conceptual relationship: the Web uses Internet infrastructure; the Internet also carries many other services.

Remember: not everything on the Internet is a website, and the Internet is not the same thing as a browser.
03 / The vocabulary

Essential terms in web design

It is difficult to build or evaluate a website without knowing the vocabulary used by its users, designers and administrators. The terms below will recur throughout the course.

Webpage
A single web document or view, such as a library's “Opening Hours” page.
Website
A related collection of webpages or web resources associated with a domain or web presence.
Homepage
The main entry page of a website, often introducing the institution and main navigation.
Web browser
Software such as Chrome, Firefox, Edge or Safari used to access and display web content.
Web server
A computer or software service that responds to requests and delivers web resources.
Client
The device or software requesting a resource; for example, a student's browser.
URL
Uniform Resource Locator: an address that identifies where to access a resource.
Domain name
A human-readable name used to locate Internet resources, such as example.org.
DNS
Domain Name System: helps translate domain names into network addresses used to reach services.
Hyperlink
A clickable or selectable connection to another page, resource or location.
Hosting
Providing the server infrastructure and services that make web content available.
HTTP / HTTPS
Protocols used to request and transfer web resources. HTTPS protects data in transit using encryption.

One practical example

A user opens a browser and enters the website address of a library. The browser contacts the appropriate server and displays the homepage. The user follows a hyperlink to “Opening Hours”. That second page belongs to the same website. The human-readable part of the address is the domain name; a hosting service may operate the server that supplies the content.

How does a webpage reach your browser?

05 / Addresses

Understanding a URL

A URL tells a browser where to find a resource and how to access it. Consider this fictional example:

https://library.example.org/catalogue/search?keyword=history

Protocol: https tells the browser how to communicate. Host: library.example.org names the destination. Path: /catalogue/search identifies a resource or route. Query: keyword=history supplies an extra parameter to the request.

Interactive URL analyser

Protocolhttps

The example uses the reserved example.org domain for teaching. It is not a real library site.

Not every URL contains all possible parts. URLs can also include a port number or a fragment such as #contact. A domain name is only one part of the full URL.

06 / The building blocks

HTML, CSS and JavaScript: different jobs

Modern webpages combine several technologies. For this course, imagine that you are preparing an information desk or reading room:

HTML — Structure

Like arranging the service desk, noticeboard and shelves. Defines headings, paragraphs, links, tables and forms.

CSS — Presentation

Like choosing signage, colours and spacing so everything is clear and consistent.

JavaScript — Behaviour

Like making a service counter respond to an action: opening a menu or checking entered information.

HTML stands for HyperText Markup Language. CSS means Cascading Style Sheets. JavaScript is a programming language commonly used to add interaction and other behaviour to websites.

Your first HTML page

An HTML document generally begins with a doctype declaration, followed by the <html> element. The <head> contains information about the document, while <body> contains content that normally appears on the webpage.

<!doctype html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My Information Service</title>
</head>
<body>
  <h1>Welcome to our information service</h1>
  <p>We help people find reliable information.</p>
  <h2>Our services</h2>
  <ul>
    <li>Information enquiries</li>
    <li>Collection access</li>
  </ul>
</body>
</html>

Try it: edit and preview the HTML

Change the main heading, the introductory paragraph or one service in the list. Select Run preview to see the result. The preview uses an isolated frame and does not run JavaScript.

To work on your own computer, download the starter files from Resources, edit index.html and open it in a browser.

Avoid a common confusion: HTML uses tags such as <h1> and <p> to mark up content. It is not a general-purpose programming language in the way JavaScript is.
07 / Different websites

Types of websites and hosting

Websites have different purposes: informing, communicating, collecting user input, providing searchable resources or offering transactional services. Their technical implementation can be simple or complex.

Static and dynamic experiences

A static webpage can be delivered as files such as HTML and CSS without a server computing personalised content for every request. A page showing opening hours is a useful example. A dynamic web application can generate or update content using server-side logic, databases, APIs or browser-side behaviour. A library circulation system with authenticated accounts and live borrowing information is a typical example.

Important distinction: a static website can still have JavaScript interactions. Conversely, many interactive services also need secure server-side functions. “Static” does not mean “unusable” or “without buttons”.

Common hosting options — awareness only

OptionTypical useConsideration
Static hosting (e.g. GitHub Pages)Course projects, documentation and public information sitesNo built-in application database or custom server-side code

Domain name and hosting are related but distinct. A domain identifies a destination; hosting provides the service or infrastructure that supplies website content. Later in the course you will learn how to publish a static class project using GitHub Pages.

08 / Your professional world

How can the Web support your profession?

Information professionals help people discover, organise, retrieve, preserve and use information. Websites can make public service information easier to find. Good design is therefore part of effective service delivery, not merely decoration.

Case A: University library information website

A student needs to find opening hours, learn how to borrow books and locate the online catalogue. A clearly organised library website can reduce unnecessary enquiries and make these services easier to discover.

Useful public webpages: Home, About the Library, Services, Opening Hours, Catalogue Access and Contact.

Design question: can a first-year student find the catalogue link within a few seconds?

Case B: Records-centre information website

A visitor needs information about records-access procedures, forms and office opening hours. A clear public information website can explain how to make a legitimate request without revealing protected records.

Useful public webpages: Home, Public Services, Request Procedures, Access Policy, Visiting Hours and Contact.

Design question: can a visitor understand which records may be requested and what authorisation is needed?

Common design principles

  • Purpose: start by identifying the user and the task they need to complete.
  • Clarity: use meaningful headings, understandable labels and plain language.
  • Navigation: keep important links easy to find.
  • Accessibility: support readers using different devices and assistive technologies.
  • Privacy: never publish confidential records, private patron information, passwords or internal access links.
  • Accuracy: provide reliable, current and properly maintained service information.

In Unit 2, you will practise planning a website layout around these user needs.

PRACTICAL 1 • WEBSITE INVESTIGATION

Inspect an information-service website

  1. Find one public library or records-centre website. Use an authentic institutional website rather than a social media page.
  2. Record the website name and its URL, then identify the domain name.
  3. Identify its homepage, three navigation links, two types of information and the intended audience.
  4. Explain one thing the website does well and one aspect that could be improved.
  5. Identify whether any links lead to a searchable or authenticated application. Explain why this is different from a simple information page.

Deliverable: a brief investigation report or the completed first part of the worksheet.

12 / Wrap up

Summary and next steps

  • The Internet is the underlying network; the Web is one system of information services that uses it.
  • A website usually comprises linked pages or resources, accessed through a browser and identified by URLs.
  • Browsers make requests; servers send responses; the browser displays the resulting content.
  • HTML structures content, CSS controls presentation, and JavaScript adds behaviour.
  • Hosting makes web resources accessible, while domains help people find them.
  • Library and records websites should be clear, user-centred, accessible and protective of sensitive information.

Key reflection

If you were responsible for the homepage of a library or records centre, what would visitors most urgently need to find? Bring your answer to Unit 2, where we will learn how to plan good web design.
