01 / From one page to a website

What you will learn

In Unit 3, you created a webpage using headings and paragraphs. A useful website usually contains several connected pages. Visitors need to move between those pages, locate services quickly and understand what each page contains.

Consider a community library. A visitor might start on its homepage, follow a link to opening hours, then read the borrowing guidelines. A records-centre visitor might need to find public access procedures and an office contact address. Unit 4 shows how to connect and organise such content with HTML.

By the end of this unit, you should be able to:

  1. Create hyperlinks to webpages and resources using <a> and href.
  2. Distinguish absolute URLs from relative file paths and use both correctly.
  3. Create links to sections within a webpage and appropriate contact links.
  4. Represent information using ordered, unordered and description lists.
  5. Insert images with <img> and write useful alternative text.
  6. Use semantic HTML to organise headings, navigation, main content and footers.
  7. Build a small, linked website for a fictional library or records centre.
Your starting point: If you already have an index.html from Unit 3, keep a copy. You can extend it by adding navigation and new pages. The exercise also includes a ready-made starter ZIP.

02 / Connecting resources

Hyperlinks: the anchor element

A hyperlink is a connection that lets a visitor open another webpage, section, file or resource. In HTML, the <a> (anchor) element creates a link. The href attribute states the destination, while the words between the tags are what people can click or activate with a keyboard.

<a href="https://www.w3schools.com/html/">Read the HTML tutorial</a>

Here href holds a complete address, and the visible words explain what the user will find. Use descriptive link text; Borrowing guidelines is more informative than Click here, especially when navigating with screen-reading software.

Link typeExamplePurpose
External webpage<a href="https://example.org">Visit website</a>Opens a resource at another web address.
Internal webpage<a href="services.html">Our services</a>Moves to another file in the same folder.
PDF or document<a href="guidelines.pdf">Download guidelines (PDF)</a>Links to a resource, which the browser may display or download.
Same-page section<a href="#hours">Opening hours</a>Moves to an element with id="hours".

Use target="_blank" only when opening a separate tab has a clear benefit, and tell readers when that will happen. For an external new-tab link, rel="noopener noreferrer" prevents some unwanted cross-window access and limits referral information; it is not required for ordinary same-tab navigation.

Common mistake: A link to services.html works only if a file with that name exists at the expected location. HTML does not create the destination file automatically.
03 / Where is the file?

Absolute and relative file paths

A file path tells the browser where to find a file. An absolute URL gives a full web address, such as https://example.org/help.html. A relative path identifies a file in relation to the location of the current HTML document.

For example, imagine this folder structure:

information-site/
├── index.html
├── pages/
│   ├── services.html
│   └── contact.html
└── assets/
    └── img/
        └── reading-room.svg
Starting fileDestination fileCorrect path
index.htmlpages/services.htmlhref="pages/services.html"
pages/services.htmlpages/contact.htmlhref="contact.html"
pages/services.htmlindex.htmlhref="../index.html"
index.htmlassets/img/reading-room.svgsrc="assets/img/reading-room.svg"
pages/services.htmlassets/img/reading-room.svgsrc="../assets/img/reading-room.svg"

Read a relative path from the folder containing the current webpage, not from the website homepage. ../ means “move up one folder”. ./ means the current folder (often optional). File names and letter case should match exactly when publishing.

Remember: /images/photo.jpg usually starts at the website root when hosted. It can behave unexpectedly in a locally opened file or a GitHub Pages project site. Prefer relative paths for this beginner project.
04 / Move within a page

Section anchors and contact links

Long webpages become easier to use when visitors can jump to a meaningful section. Add a unique id to the destination element, then link to # followed by that ID.

<a href="#opening-hours">Jump to opening hours</a>

<h2 id="opening-hours">Opening hours</h2>
<p>Monday to Friday: 08:00–17:00.</p>

You can also link directly to a section on another page with href="services.html#membership". The destination page must contain an element with id="membership".

<a href="mailto:info@example.org">Email the service desk</a>
<a href="tel:+255000000000">Telephone the office</a>

mailto: can open the visitor’s email application, and tel: can open a calling application on supported devices. Neither automatically sends a message or creates a working contact form.

When linking to a file or document, mention its format when useful, for example “Records request guidance (PDF)”. Avoid links labelled only “here”.

05 / Presenting collections and steps

HTML lists for clear information

Lists make related items easier to scan. HTML provides three useful kinds of list: unordered, ordered and description lists. Choose the list type based on meaning, not simply on how it looks.

Unordered list: items with no sequence

<h2>Library services</h2>
<ul>
  <li>Reading spaces</li>
  <li>Reference support</li>
  <li>Internet access</li>
</ul>

The <ul> element groups bullets; each item is an <li>.

Ordered list: steps in sequence

<h2>How to request a public record</h2>
<ol>
  <li>Check the access guidance.</li>
  <li>Identify the relevant record.</li>
  <li>Contact the responsible office.</li>
</ol>

The <ol> element represents steps where order matters.

Description list: words and definitions

<dl>
  <dt>Catalogue</dt>
  <dd>A searchable description of library resources.</dd>
  <dt>Archive</dt>
  <dd>Records retained for their continuing value.</dd>
</dl>

A description list uses <dl>, <dt> (term) and <dd> (description). It is useful for glossaries and definitions. A numbered list should not be used for unrelated services merely to decorate them with numbers.

06 / Visual information

Adding images responsibly

The <img> element places an image in a webpage. It is a void element, so it has no closing tag. Its src attribute names the image file; its alt attribute provides a text alternative when the image cannot be seen or loaded.

<img src="assets/img/reading-room.svg"
     alt="Tables and bookshelves inside a library reading room"
     width="640" height="360">

An image's width and height are usually expressed in CSS pixels and help reserve space. They do not replace responsive CSS. For large images further down a page, loading="lazy" can delay loading until needed.

Informative image

For a photograph showing the entrance to an archive, alt text could be: “Entrance to the archives reading room, beside the reception desk.” The description communicates information the image contributes.

Decorative image

For an ornament that adds no information, use alt="". Screen readers can then ignore the decoration rather than announcing irrelevant details. Do not omit the alt attribute.

Figure and caption

<figure>
  <img src="assets/img/reading-room.svg"
       alt="Library reading tables and shelves">
  <figcaption>Example reading-room facilities.</figcaption>
</figure>

A <figure> groups a visual with optional <figcaption>. The caption and alternative text have different jobs: the caption is visible contextual information; alt text describes the image for people who cannot see it.

Professional practice: Use images you created, images you have permission to use, or appropriately licensed assets. Never include identifiable borrowers, confidential files or protected records in public examples.
07 / Meaningful document regions

Semantic HTML and page landmarks

Semantic HTML uses elements whose names describe the role of content. These labels help browsers, assistive technologies and maintainers understand the page.

ElementTypical purposeInformation-service example
<header>Introductory content, often site titleName and identity of a library website
<nav>A set of navigation linksHome, Services, Contact
<main>Primary content of this webpageBorrowing guidance or records procedures
<section>A thematic group, usually with headingOpening hours section
<article>Self-contained contentA news or service announcement
<footer>Supporting or concluding contentOffice address and copyright notice

One page normally has one primary <main> region. Do not use <nav> just because text looks like a menu; use it when links actually provide navigation. <section> should have a meaningful topic, usually labelled by a heading.

<header>
  <h1>Community Library</h1>
  <nav aria-label="Main navigation">
    <a href="index.html">Home</a>
    <a href="pages/services.html">Services</a>
    <a href="pages/contact.html">Contact</a>
  </nav>
</header>
<main>
  <section>
    <h2>Welcome</h2>
    <p>Find books and study information.</p>
  </section>
</main>
<footer><p>Fictional learning example.</p></footer>

The aria-label gives the navigation region an accessible name. You will learn more about ARIA as needed; meaningful native HTML remains the first choice.

08 / Building a small website

Navigation, naming and information architecture

Visitors should be able to tell where they are, what pages exist and how to return to the homepage. A small service website might use three pages: Home, Services and Contact.

Example website map

Home (index.html) → overview and most important links

↳ Services (pages/services.html) → borrowing or access procedures

↳ Contact (pages/contact.html) → public contact details and hours

Use the same understandable menu labels and roughly the same navigation order on each page. If a file sits in a subfolder, its links back to the home page must use the correct path, often ../index.html.

<!-- Inside pages/services.html -->
<nav aria-label="Main navigation">
  <a href="../index.html">Home</a>
  <a href="services.html" aria-current="page">Services</a>
  <a href="contact.html">Contact</a>
</nav>

aria-current="page" identifies the link for the current page to assistive technologies. Use headings and plain language so that pages remain understandable even without elaborate colours or decoration.

Helpful distinction: A working multi-page information site does not need JavaScript. HTML links are sufficient to navigate between existing HTML files.
09 / Your professional context

Examples in libraries and records centres

Library website

Homepage: a short welcome and links to collections, opening hours and reader assistance.

Services page: an unordered list of reader services and an ordered list explaining borrowing steps.

Image: a labelled picture of a reading space with informative alt text.

Records-centre website

Homepage: an introduction to public information services and where to find access guidance.

Services page: ordered public request steps and a list of public service categories.

Privacy: no actual personal records, internal reference numbers or protected files are shown.

Both sites need descriptive links, consistent navigation, appropriate lists, meaningful images and clear contact details. The structure is transferable even though their professional content differs.

15 / Takeaways

Unit 4 summary

  • Hyperlinks connect webpages, sections and other resources through <a href="...">.
  • Absolute URLs identify complete addresses; relative paths depend on the current file’s location.
  • The ../ notation moves up a folder, while #id links to a named section.
  • Unordered lists present related items; ordered lists communicate sequence; description lists pair terms with explanations.
  • Images require a src and an appropriate alt attribute; figures can include captions.
  • Semantic elements such as header, nav, main and footer express the roles of page regions.
  • Consistent labels, navigation and sensible file organisation make websites easier to use and maintain.
