01 / Start here

What you will learn

HTML describes a webpage's content, while CSS determines how it looks. A webpage can also respond to people: a button may reveal extra instructions, a search box may highlight matching items, or a form may report an incomplete field. JavaScript is a programming language commonly used to create these behaviours in a web browser.

By the end of this unit, you should be able to:

  1. Explain the different roles of HTML, CSS and JavaScript.
  2. Recognise a basic JavaScript statement, a variable, a function and an event.
  3. Read and make small changes to scripts that respond to a button click.
  4. Explain how JavaScript can update webpage content and provide form feedback.
  5. Identify simple, appropriate uses of JavaScript in libraries and records centres, including its limitations.
Before you begin: You should already know how to write a simple HTML page, assign an id to an element, and apply basic CSS. This unit provides a gentle introduction; advanced JavaScript programming is not required.

03 / Roles of web technologies

HTML, CSS and JavaScript work together

Imagine a public library webpage that contains a list of services and a button labelled Show opening hours. These three technologies work together:

HTML

Structure and meaning

Creates the heading, paragraph, service list and button. Example: <button>Show hours</button>.

CSS

Presentation

Sets button colours, typefaces, spacing and placement. Example: button { background: teal; }.

JAVASCRIPT

Behaviour

Detects when the button is clicked and reveals information without reloading the whole page.

Remember: HTML and CSS can create useful websites on their own. JavaScript is added when an interaction genuinely helps people complete their tasks.

04 / Where JavaScript runs

JavaScript in the browser

A web browser reads HTML to form a document and applies CSS to its visual presentation. JavaScript can then interact with parts of that document, such as a button, a message or a form. The browser runs the JavaScript in response to instructions and user actions.

A client-side script runs in a visitor's browser. Other JavaScript applications can run on servers, but this unit only introduces basic browser interaction.

Example: Clicking “Show location” on a records-centre information page can reveal an already-written office address. This is different from retrieving a restricted record from a secure database.

JavaScript must not be treated as a substitute for server-side access control or secure processing of confidential records.

05 / Adding a script

Three ways to include JavaScript

As with CSS, JavaScript can be written in different places. A <script> element tells the browser where to find it.

1. Internal script

<script>
  console.log("Library page ready");
</script>

Small scripts may appear in a webpage, commonly near the end of <body>. console.log() sends a message to the browser developer console; it does not display the message on the webpage.

2. External script

<script src="script.js" defer></script>

This loads JavaScript stored in another file. An external file is useful when several webpages share behaviour. The defer attribute lets a traditional external script wait until the HTML has been parsed before it executes.

3. Inline event code

<button onclick="alert('Hello')">Greet</button>

Inline event attributes exist, but separating JavaScript from HTML generally makes code clearer to read and maintain. In the practical examples, events are connected using addEventListener().

06 / Understanding statements

Statements, comments and basic values

A statement is an instruction. JavaScript is case-sensitive: showMessage and showmessage are different names. Statements often end with semicolons, although many are optional.

// One-line comment
const institution = "Community Library";
const openDays = 6;
const isOpen = true;

const declares a variable whose binding cannot be reassigned. let declares a variable that may be reassigned. The three values above illustrate a string (text), a number and a Boolean (true or false).

Comments beginning with // explain code for readers; they are ignored as executable statements.

Try reading the code: const count = 3; stores a number. let clicks = 0; may later become clicks = clicks + 1;.
07 / Reusable instructions

Functions and simple conditions

A function is a named block of instructions that can run when called. A condition lets a script make a choice.

function serviceMessage() {
  return "Ask at the information desk.";
}

const visitors = 4;
if (visitors > 0) {
  console.log(serviceMessage());
}

function defines reusable behaviour, return supplies a result, and if executes a block when its condition is true. This is a small example; more complicated programming structures are outside the scope of this course.

08 / Connecting code to HTML

The Document Object Model (DOM)

When a browser reads HTML, it builds a representation of the document called the Document Object Model (DOM). JavaScript can locate elements in that representation and change what visitors see.

<p id="notice">Welcome.</p>

<script>
  const notice = document.getElementById("notice");
  notice.textContent = "Welcome to the library.";
</script>

The id identifies an element. document.getElementById("notice") locates it, and textContent updates the text inside it. The element must exist when the script runs.

Important: Prefer textContent for ordinary messages rather than inserting user-provided HTML. It treats content as text, reducing the risk of unwanted markup or scripts being interpreted.

09 / Responding to actions

Events and event listeners

An event is something that happens on a webpage, such as clicking a button, typing into a field or submitting a form. An event listener tells JavaScript what to do when that event occurs.

<button id="hoursButton">Show hours</button>
<p id="hours"></p>

<script>
  document.getElementById("hoursButton")
    .addEventListener("click", function () {
      document.getElementById("hours").textContent =
        "Monday–Friday, 08:00–17:00";
    });
</script>

When the button is clicked, its listener runs. This example changes the paragraph without navigating to another page.

10 / A complete example

Example: Reveal library or records-centre information

A short script can make general public guidance easier to find. The example below uses an accessible button and changes the text of a message.

<button id="details" type="button">Show service details</button>
<p id="message" aria-live="polite">Select the button.</p>
<script>
  const button = document.getElementById("details");
  const message = document.getElementById("message");
  button.addEventListener("click", () => {
    message.textContent = "Enquiries: Information Desk, Room 2";
  });
</script>

aria-live="polite" can help assistive technologies announce a changed message without interrupting the visitor immediately. Buttons should also remain usable from a keyboard.

11 / Forms and feedback

Simple form checking and helpful messages

HTML can require a field using the required attribute. JavaScript can provide additional feedback, such as telling a visitor that a fictional enquiry needs a short description.

const form = document.getElementById("requestForm");
const message = document.getElementById("feedback");
form.addEventListener("submit", function (event) {
  event.preventDefault(); // Stay on this practice page
  message.textContent = "Practice request checked.";
});

event.preventDefault() stops the form's usual submission behaviour. In a practice page, this can demonstrate feedback without sending information anywhere.

Security distinction: Checking a form in JavaScript does not prove that its contents are correct, does not save the data and does not securely submit it. Real requests require a trusted server-side process, suitable permissions and appropriate privacy protections.
12 / Useful and inclusive interactions

Good interaction design

  • Use meaningful controls: choose a real HTML <button> for an action instead of a clickable paragraph.
  • Give visible feedback: after an action, say what changed or what the visitor needs to correct.
  • Support the keyboard: buttons and form controls should work without a mouse.
  • Do not rely only on colour: provide text explanations for warnings or errors.
  • Keep essential information accessible: opening hours or public procedures should remain discoverable even when a script fails.

A website that adds excessive pop-ups, animation or unnecessary interactions may become harder to use rather than better.

13 / Professional applications

JavaScript in information services

LIBRARY & INFORMATION STUDIES

Library service page

  • Show or hide guidance about book requests.
  • Filter a short, fictional reading list on a practice webpage.
  • Display an explanatory message when a visitor selects a library service.

Boundary: a real catalogue search normally needs an authorised catalogue service or backend.

RECORDS MANAGEMENT SYSTEMS

Records enquiry page

  • Reveal public instructions for requesting a document.
  • Show the correct department for a public enquiry category.
  • Provide immediate feedback about missing form fields.

Boundary: access to restricted records must be enforced securely, not hidden or granted by client-side JavaScript.

19 / Remember the essentials

Unit 10 summary

  • HTML provides page content and structure; CSS styles it; JavaScript can add interaction.
  • JavaScript statements can store values, make simple decisions and define functions.
  • The DOM represents webpage elements that scripts can read or update.
  • Events such as click trigger scripts attached with event listeners.
  • JavaScript can provide helpful form feedback, but client-side validation is not secure processing.
  • Keep interactions understandable, keyboard-operable and appropriate to visitors' needs.
  • JavaScript cannot, by itself, securely authenticate users, protect restricted records or store requests in an institutional database.
